# Bundled proof approval pages

- Each page lives at `p/<slug>/index.html` with images in `p/<slug>/img/`.
- Build new pages by copying the CTNx page (`p/abd4567daaae/index.html`) as the base. It has the standard features every new page must have:
  - Red "Change in progress" overlay on items where the client requested changes (`.wipwrap` / `.wip`).
  - Approved items collapse to a slim green row (`.card.mini`) with a thumbnail; tap "View" to open, "Collapse" to close.
- No "Your items" checklist at the top (Christie decided it was redundant).
- If you copy a different page, port all of the above over. Older pages are left as they are.
- The order number always shows as small, muted "Internal PO #1234" text after the order name in the heading, not full size. Set `ORDER.name` to "Order Name #1234" and use the heading script from the Rocket page (`p/34fb96234786`), which splits off the "#1234" and renders it small.
- Proof images stay at the standard size: no wider than 340px and no taller than 440px (CSS `.single img{width:auto;max-width:min(100%,340px);max-height:440px}`), so tall narrow items like tumblers and bottles don't tower over the page. Exception: stacked proof + actual-size artwork images (e.g. OGIO from Pinnacle) set `tall: true`, which allows up to 680px (`.single img.tall{max-height:680px}` and add `class="tall"` when `it.tall`). New pages must include both CSS rules. Do not set `wide: true` on apparel; they must not stretch to full page width.
- With the actual-size box removed, a side-by-side proof sheet becomes just the mock-up, so it shows at normal size. Do not stack or keep actual-size artwork on new pages.
- Christie pastes uncleaned vendor proofs. Clean each to just the mock-up: remove "Item #", "imprint color(s)", and the vendor text above collars/hoods (even where it overlaps the garment; redraw a clean edge). Also remove all size markings: "Actual size" logo boxes, "50% of actual size" / "Left chest - actual size" labels, and rulers. The page rescales proofs, so those markings are no longer accurate (Christie's rule, Nov 2026; replaces the old "keep size info" rule). No vendor names, mockup IDs, or copyright lines.
- Item names come from the vendor invoice when she provides one, in invoice order.
- Proof backgrounds are plain white: replace any colored or patterned vendor background with white so every item matches. Keep the dashed imprint-area outline on the product.
- Out-of-stock replacements: always show the client's original choice FIRST as an option with `"orig": "Your original choice"`, `"tag": "Out of stock"` and `"unavailable": true` (greyed out, can't be picked; see BASF #3490 `p/3df9a12740c4` for the render code, port it if the base page lacks it). Name the original in the cordial attention note, then list the replacement options A, B, C… Get every option's photo and details yourself from the product links Christie gives (Faire blocks downloads, so link the cdn.faire.com image directly; open a Faire page Christie's Chrome can see if WebFetch is blocked). Never ask her for the photos. If she asks for replacement options but doesn't give the original item, ask her for it before building, so it can be shown.
- Custom printed boxes (inside + outside artwork): don't use screenshots of the box store's 3D preview (labels/angles came out wrong). Use the shared folding 3D viewer `assets/box3d.js` (see AUSL #3493 `p/88c922b82035`, item `box3d`): fetch the designer's clean flat render for Outside and Inside (the preview `img` URL with `pixel=0.25mm`), make RGBA textures (grey background transparent; inside unprinted = white, alpha mirrored from outside), set the fold-line pixel coordinates, and label the "Show me" views by what's printed on each side. Also show both flat artworks with "Open full size". Spin slowly (spinSpeed ~2.2).
